## 操作

0.1.4 针对“安装成功但开始游戏返回桌面”的实机反馈降低运行时内存压力：原作字库轮廓从 2,201,596 字节减至 870,580 字节；英文恢复正常字符与词间空格，混合文本按实际宽度换行。邮件、论坛正文按需读取，提前加载的相关资源由 455,401 字节减至 132,150 字节；剧情最多缓存三块、40,000 个源字符；回看历史最多八句且合计约 48,000 个字符，复杂场景可能少于八句。30 个存档只在列表中保留预览，选中后才读取完整状态。初始状态由原作 VM 离线执行生成，比较全部 2,048 种通关标志组合，避免启动时重复执行 86 次系统宏跨块跳转；后续仍执行完整剧情与选择。原作零寄存器采用稀疏存储，日期、图像透明度、分支和手机状态保留。

通讯录按原作 `PhoneSG_0F/10/11` 加入、移除和重置；例如红莉栖、萌郁、铃羽等联系人随原作剧情开放，临时联系人也会消失。0.1.3 及更旧版本存档沿用原键名和剧情位置，旧档缺少通讯录时按原作脚本顺序恢复。借用手机仍隔离短信并按当前剧情开放操作。

转换阶段折叠 639 个常量表达式，将 23,770 条相邻赋值合并为 7,125 个计算组，并在覆盖前没有读取时省去 449 个常量写入。跳转、标签、电话、邮件和图像指令保留；手机等待边界和原脚本位置保持不变，跨预算边界或从旧档的组内位置继续时保留必要的中间写入。六条结局逐帧比较全部 VM 状态与文本／选项，均与合并前一致，解释器分发减少约 35.5%；这不等于运行耗时减少 35.5%，也没有穷举所有可选邮件组合。详见 `reports/story-optimization.json`。

0.1.3 的实机启动崩溃未取得固件日志，因此无法确认唯一根因。新版针对字库、预载资源、缓存、历史和初始化的峰值做了削减；官方模拟器结果不能代替固件上的完整验证，最新实机反馈仍有卡顿。标题保留原作静态封面，本版暂未加入旋转动画。

开始游戏会执行原作的完整主流程。图片置于界面上方，对话框置于下方；长文本可以滚动，轻触对话正文或点击“下一句”推进；逐字显示时首次轻触会显示完整句子，再次轻触推进。滑动不会翻句。底部依次为“上一句、菜单、手机、下一句”。菜单提供保存、读取、字号、显示速度、下一章和返回标题。台词首尾的半括号不显示，句中引用保留。台词按当前字号显式换行，并可上下滑动；修改字号会重新排版。对话框上方显示原作 W1430 的故事日期，例如“（日期：07.28）”，不再把脚本段号误标为日期。

原作在手机上完成的交互改为手表选择面板。收到邮件时可打开或暂不阅读；回复面板保留原作的关键词及其邮件编号，顶部邮件正文可以上下滚动。电话操作可拨打、发送或不操作；D-Mail 提供发送和不发送选项。电话微波炉的输入映射沿用原作跳转表。

关闭手机后，可用底部“手机”再次打开当前仍有效的电话、发送邮件或 D-Mail 操作；“短信／邮件”可以查看已收和已发送记录，“联系人”只允许执行当前原作开放的操作。借用绯莉丝、萌郁和 FB 的手机时显示机主，并隔离记录与可操作联系人。回复时机已过的邮件只允许查看，不能补选答案来改变已结束的分支。D-Mail 的“不发送”保留当下阅读时段的手机入口，原作关闭该操作时段后收回权限。

“下一章”按原作大章边界前进，遇到邮件、电话、D-Mail 等交互会停止，必须先作出选择。它不会代选答案。

对于原作持续等待手机操作的段落，选择“关闭手机，继续剧情”不会清除可操作状态；再次快进会停在手机面板，并显示“剧情正在等待手机操作”，不会反复执行等待循环直到报错。

## 安装与异常处理

1. 使用“表盘自定义工具”传输 `.bin` 安装包；传输完成后等待手表完成解包和安装，期间保持连接。
2. 首次测试建议保留一个可恢复的稳定版本。安装和首次资源读取可能需要一段时间。
3. 若应用无响应，先使用手表系统返回操作；无法退出时先重启手表，再重新打开或重装应用。未手动保存的进度可能丢失。
4. 若安装失败，先检查工具状态、安装器空闲状态及存储，尝试卸载该应用后重新安装。包体约 22.75 MB，但解包后的原始文件约 27.9 MB；文件系统分配单位、传输暂存和覆盖安装临时目录会使实际空间需求更高。
5. 重装可能清除本应用存档。不要一出现问题就恢复出厂设置；若恢复出厂设置是最后的处理手段，应先确认并备份个人数据。

安装包只使用应用 API，没有固件刷写、设备配置修改或后台联网代码。不能保证所有固件上不会崩溃，也不能用模拟器检查替代实机验证。

## 移植原理

MPK 资源归档以只读方式提取。SC3 脚本通过 MgsScriptTools 反汇编，再编译为分块 JSON 指令；运行时解释分支、调用栈、整数变量、邮件状态及资源加载。单次解释设置指令预算，跨块读取异步执行，防止长段落阻塞界面。

相较于此前几个项目较直接的场景更新，本版为对齐原作图像保留了背景／角色缓冲交换、图层状态及跨脚本演出宏，还需要手机与邮件分支。静态阅读过程中仍有大量原作演出寄存器计算；宏和剧情分块来回读取也会放大手表存储延迟。原作私用区字体、预载邮件、完整回看状态叠加增加内存压力。0.1.4 将这些负担分别移至转换阶段或改为有上限的按需读取；目前没有取得实机崩溃日志，不能将这一分析当作已证实的单一崩溃原因。

这份简体中文资源的字符编号与日文字符表不一致。转换器保留原作 glyph ID，映射到私用区字符，并从原作 `FONT.PNG` 生成配套字体；没有通过 OCR 重写台词，也没有使用日文字表猜测中文。复制源码里的私用区文本到普通编辑器会看见特殊字符，必须配合生成字体显示。

不透明背景缩小至最多 320 × 240 的非渐进 JPEG，透明叠加层使用 PNG；根据脚本生成静态裁切和遮罩。立绘解析 PNG/LAY 图块与原作表情层，保留透明度与坐标，以最多 176 × 288 的图像绘制可见身体。原作 1920 × 1080 画面等比放在上方 432 × 243 的区域，文本框在下方，避免把 CG 拉伸填满屏幕。CG 鉴赏将已核对的三个叠加素材合成为完整场景；另七张未在六条主流程中观察到的透明图层仍作为原始差分素材保留，清单见 `reports/gallery-composition.json`。

本版不包含语音、BGM、影片、Steam 成就和原作手机界面的完整动画。转场、闪烁、部分叠加特效和随机邮件到达等待被简化；TIPS 词典和手机壁纸收藏暂未提供完整界面。主剧情与邮件的文本按原作资源显示，不能将本应用理解为原生 Windows 引擎的等价实现。

## 构建与检查

环境：Node.js，Python（Pillow、NumPy、OpenCV、fontTools、cryptography），原作资源反汇编另需 .NET 8。兼容编译器固定为 `aiot-toolkit@1.1.0`。项目已包含生成后的图文资源，可以直接构建。

```powershell
npm install --prefix tools/compat-toolkit --ignore-scripts aiot-toolkit@1.1.0
$env:WATCH_COMPAT_TOOLKIT = (Resolve-Path tools/compat-toolkit/node_modules/aiot-toolkit).Path
node tools/build.cjs
python tools/audit-package.py PATH_TO_VELA_DEFAULT_FONT.ttf
```

完整资源重建流程：运行 `prepare-source.py` 提取 `script.mpk`、字库和系统标题资源；用 MgsScriptTools 与 `tools/sc-spec-bank` 反汇编；依次运行 `build-original-font.py`、`convert-assets.py`、`compile-story.py`、`finish-assets.py`、`regroup-gallery.py`、`generate-maps.py`。0.1.2 还需运行 `repair-graphics-assets.py` 保留透明度和坐标，执行六条路线生成图像状态报告，再运行 `build-background-variants.py`、`build-gallery-scenes.py`、`build-visual-recovery.py`、`alias-default-faces.py`、`archive-obsolete-images.py` 和 `generate-maps.py`。中间目录默认为项目同级 `steins-probe`；原作位置通过 `STEINS_GAME_ROOT` 指定。`tools/source-provenance.json` 记录参考工具与版本。

包检查需要额外提供官方 Vela 默认字体文件，以核对普通界面字符；原作私用区字形已经包含在项目中。

原作完整流程检查：`node tools/verify-routes.cjs`。手机与邮件检查：`node tools/audit-phone.cjs`。单元检查：`node --test tests/*.test.cjs`。这些检查直接读取项目内的剧情分块和邮件资源，不需要另行安装原作。

0.1.4 的 `compile-story.py` 末尾调用 `optimize-story.cjs`，参考指令流保存为 `tools/story-reference.json`。资源重建后执行 `node tools/prepare-runtime.cjs` 生成按需加载资源、通讯录恢复表和通关标志对应的首句状态补丁；再执行 `node tools/verify-optimization.cjs` 逐帧对照优化前后，执行 `node tools/verify-routes.cjs --lazy` 检查实际按需读取流程。字体重建会同时生成英文比例宽度表。

### 官方模拟器预览

以下 PowerShell 命令在项目目录执行。模拟器环境与应用源码分开保存；已有官方 SDK 时可将 `WATCH_SDK_HOME` 指向其路径，首次下载会较大。

```powershell
npm install --prefix tools/emulator-runtime --ignore-scripts @aiot-toolkit/emulator@2.0.5 @miwt/adb@0.9.1
$env:NODE_PATH = (Resolve-Path tools/emulator-runtime/node_modules).Path
$env:STARRY_EMULATOR_HOME = Join-Path (Get-Location).Path '.emulator'
$env:WATCH_SDK_HOME = Join-Path $env:STARRY_EMULATOR_HOME 'sdk'
node tools/setup-emulator.cjs
node tools/emulator-server.cjs
```

打开 `http://127.0.0.1:43130/` 查看原生屏幕。控制服务仅绑定本机回环地址；测试脚本会安装当前构建，操作原生界面并保存截图。

另开终端设置同样的 `STARRY_EMULATOR_HOME`，执行 `node tools/native-check.cjs`。出现 `NATIVE_PREPARE_PASSED` 后，在运行控制服务的终端通过控制服务的 `/shutdown` 将整个模拟器关闭，再重新运行 `node tools/emulator-server.cjs`，再执行 `node tools/native-check.cjs --installed --after-cold`。在冷启动前先执行 `node tools/native-text-check.cjs`，检查 28 字号长台词、后续长邮件的滚动，以及滑动不推进／不代选。第二阶段保留设备用户数据，检查四个存档、待选邮件以及关闭后的手机操作能否恢复，不重新安装应用。
